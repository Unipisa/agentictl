# GitHub Readiness Requirements

Before promoting the project publicly on GitHub:

- README must explain the threat model, install path, SSH model, tests, and package flow.
- Requirements must document how new verbs are accepted.
- CI must run the Docker SSH test harness.
- Generated tarballs should be published as release artifacts rather than committed routinely.
- The project should choose an explicit license before public release.
- Security-sensitive changes should include Docker SSH tests.

Recommended repository topics:

```text
ssh
linux
sysadmin
agents
openclaw
automation
devops
safe-executor
```
